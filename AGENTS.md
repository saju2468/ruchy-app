# Ruchy Restaurant App - Project Context & Memory

> **Source of Truth**: This document serves as the project memory and architectural blueprint for **Ruchy** (a Swiggy-inspired restaurant & food ordering application). It reflects the current code state and future development plan.

---

## 1. Project Overview & Architecture

Ruchy is a modern food discovery and delivery web application inspired by Swiggy. While development and testing currently use Bangalore coordinates as a baseline, Ruchy is designed as a location-based food delivery platform where restaurants and menus are dynamically loaded according to the user's current or selected location.

### High-Level Architecture

## 3. Vite & Tailwind CSS v4 Setup

### Vite Setup (`vite.config.js`)
- **Plugin Integration**: Uses `@vitejs/plugin-react` and `@tailwindcss/vite`.
- **Root Directory**: `root: "frontend"` specifies the client root.
- **Build Output**: `outDir: "../dist"`, `emptyOutDir: true`.

```javascript
import react from "@vitejs/plugin-react";
import { defineConfig } from "vite";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
  root: "frontend",
  build: {
    outDir: "../dist",
    emptyOutDir: true,
  },
});
```

### Tailwind v4 Configuration (`frontend/src/index.css`)
- **Modern Import**: Relies on `@import "tailwindcss";` (no `tailwind.config.js` required in Tailwind v4).
- **Custom Global Styles**:
  - Font applied to `body`: `'Montserrat', sans-serif`.
  - Max container width: `.container` (`max-width: 1700px; padding: 0 40px; margin: auto;`).
  - Shimmer card grid styles (`.shimmer_container`, `.shimmer_card`).
  - Hidden scrollbars (`::-webkit-scrollbar { display: none; }`).

## 4. React Router & Navigation Architecture

Implemented in `frontend/src/main.jsx` using `createBrowserRouter` and `RouterProvider` from `react-router`:

### Route Hierarchy
- **Parent Layout Route**: `/`
  - Elements: `<Header />` with nested `<Outlet />`
  - Error Boundary: `<Error />` (catches 404 and unhandled routing exceptions)
- **Child Routes**:
  - `index: true` (`/`) &rarr; `<Home />` (displays `<BestRestaurants />`)
  - `path: "about"` (`/about`) &rarr; `<About />`
  - `path: "restaurant/:resId"` &rarr; `<RestaurantDetails />` (dynamic route parameterized by restaurant ID)

## 5. Current Frontend Implementation Details

### Component Breakdown

1. **Header (`Header.jsx`)**
   - Brand logo (`/logo.png`) linking to `/`.
   - Navigation links: `Offers` (`/`), `About` (`/about`), `How it works` (`/`), `Help` (`/`).
   - Action icons: User profile (`<User />`) and Shopping Cart (`<ShoppingCart />`).
   - Sticky/styled banner container with cream background (`bg-[#fcf2e8]`).

2. **Home (`Home.jsx`)**
   - Main wrapper with `.container`.
   - Hosts `<BestRestaurants />`.
   - `<Banner />` is available and ready to toggle on as hero section.

3. **BestRestaurants (`BestRestaurants.jsx`)**
   - **State**:
     - `listOfRestaurants`: Live restaurant array fetched from Swiggy API.
     - `searchText`: Value bound to `<SearchBar />`.
     - `isTopRated`: Toggle state for top-rated filter.
   - **Filtering Logic**:
     - Top Rated: Filters for `avgRating > 4.3`.
     - Search: Case-insensitive substring matching against `restaurant.name`.
   - **Render States**:
     - Loading: Renders `<Shimmer />` skeleton.
     - Empty results: Renders "No restaurants found matching your search".
     - Populated: Renders 4-column responsive grid (`grid-cols-4 gap-5`) of clickable `<RestaurantCard />` items wrapped in `<Link to={`/restaurant/${restaurant.id}`}>`.

4. **RestaurantCard (`RestaurantCard.jsx`)**
   - Visual card with hover elevation (`hover:shadow-2xl transition-all duration-200`).
   - Displays Cloudinary image via `${RestaurantCardImage}${cloudinaryImageId}`.
   - Displays restaurant name, comma-separated cuisines, area name with `<MapPin />`, star rating with `<Star />`, and delivery time SLA string with `<Clock />`.

5. **SearchBar (`SearchBar.jsx`)**
   - Rounded pill input with search icon, interactive focus state, and real-time state binding.

6. **Button (`Button.jsx`)**
   - Branded orange button (`bg-orange-600 hover:bg-orange-700 text-white`).

7. **Shimmer (`Shimmer.jsx`)**
   - 3-column placeholder skeleton while data is fetching.

8. **Error (`Error.jsx`)**
   - Fullscreen 404 / error display (`page not found : 404`).

## 6. Swiggy API Integration

### 1. Restaurant Listing API
- **Endpoint**:
  ```
  https://www.swiggy.com/dapi/restaurants/list/v5?lat=12.9338752&lng=77.6301732&is-seo-homepage-enabled=true&page_type=DESKTOP_WEB_LISTING
  ```
- **Location Target (Development & Testing)**: Bangalore coordinates (`lat=12.9338752`, `lng=77.6301732`) are used as a development baseline. The architecture is designed to accept dynamic latitude and longitude values based on the user's detected or chosen location.
- **Data Access Path**:
  ```javascript
  json?.data?.cards[4]?.card?.card?.gridElements?.infoWithStyle?.restaurants.map(
    (restaurant) => restaurant.info
  );
  ```

### 2. Media & Image CDN (`utilities/constants.jsx`)
- **Base URL**:
  ```javascript
  export const RestaurantCardImage = "https://media-assets.swiggy.com/swiggy/image/upload/";
  ```

### 3. Fallback / Mock Data (`utilities/mockData.jsx`)
- Contains static restaurant models (KFC, Dominos, Pizza Hut) used during offline development or API fallback.

## 7. RestaurantDetails Dynamic Routing (`/restaurant/:resId`)

### Route & Params
- Implemented in `frontend/src/pages/RestaurantDetails.jsx`.
- Uses `const { resId } = useParams()` from `react-router`.

### Menu API Endpoint
- **Live Menu Fetch**:
  ```
  https://www.swiggy.com/dapi/menu/pl?page-type=REGULAR_MENU&complete-menu=true&lat=12.9338752&lng=77.6301732&restaurantId=${resId}&catalog_qa=undefined&submitAction=ENTER
  ```
- **Restaurant Info Extracted**:
  - Name, Cloudinary image, `avgRating`, `totalRatingsString`, `costForTwo`, and `cuisines` list.
- **Next Planned Menu Enhancements**:
  - Extract category cards and item accordions from `resInfo?.cards` (e.g. `REGULAR` menu cards).
  - Render individual item cards with price, veg/non-veg indicator, description, image, and "ADD" button.

## 8. Express Backend Architecture & Plan

### Current Status
- `express` (`^5.2.1`) and `cors` (`^2.8.6`) are already present in root `package.json`.
- Folders `server/` and `backend/` are set up at the project root.

### Backend Responsibilities & Plan

1. **CORS Proxy for Swiggy APIs**:
   - Direct client browser calls to `swiggy.com/dapi/*` may face CORS blocking or origin restrictions.
   - The Express server will provide local proxy endpoints:
     - `GET /api/restaurants` &rarr; proxies the Swiggy list API with proper User-Agent headers.
     - `GET /api/menu/:resId` &rarr; proxies the Swiggy menu API.

2. **Data Caching & Fallback**:
   - Cache Swiggy responses in memory or file cache to minimize outbound rate limits and speed up local development.
   - Seamlessly fallback to mock data when upstream APIs are unreachable.

3. **Custom Application Features**:
   - Dynamic location detection & location picker (browser geolocation, address search, and passing user coordinates).
   - Cart management & persistence.
   - User authentication / session handling.
   - Order simulation and order history.

4. **Dev Script Integration**:
   - Add concurrent dev scripts (`npm run dev:all` or `concurrently`) to start both the Express backend (e.g. on port `5000`) and the Vite frontend (port `5173`).
   - Configure Vite proxy in `vite.config.js`:
     ```javascript
     server: {
       proxy: {
         "/api": "http://localhost:5000",
       },
     }
     ```

## 9. Development Guidelines & Rules

1. **Source of Truth**: Always inspect existing files in `frontend/src` before introducing new abstractions.
2. **Path Resolution**: The Vite root is `frontend/`. Static assets in `frontend/public/` are referenced with leading slash (e.g., `/logo.png`, `/banner.png`).
3. **Tailwind v4 Conventions**: Use standard Tailwind v4 utility classes. Custom variables and font definitions reside in `frontend/src/index.css`.
4. **Preserve Code Integrity**: Do not make unintended edits to application files unless explicitly requested. Maintain comments, props, and existing naming conventions.
